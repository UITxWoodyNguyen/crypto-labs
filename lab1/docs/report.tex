\subsection{Mô hình đe dọa và các kịch bản dùng sai}

\subsection{Hạn chế với ECB}
Cảnh báo, chặn trên 16 KiB, \texttt{--allow-ecb}.

\subsection{Kiểm tra IV/nonce}
Độ dài đúng theo mode, từ chối IV sai.

\subsection{Chống tái sử dụng nonce}
Logic phát hiện: \texttt{SHA-256(key | mode | iv)}, file \texttt{.aestool\_nonces}, các giới hạn.

\subsection{Fail closed}
Không ghi file khi xác thực lỗi, thông báo lỗi không lộ nguyên nhân, phân loại mã thoát.

\section{Phân tích bảo mật}
\label{sec:security-analysis}

\subsection{Mức mode}
\begin{itemize}
  \item ECB không an toàn (ví dụ pattern).
  \item Rủi ro padding oracle của CBC.
  \item Thảm họa khi dùng lại nonce trong CTR (keystream reuse).
  \item Đảm bảo của AEAD so với non-AEAD.
  \item Vì sao GCM cần nonce duy nhất.
  \item XTS không có tính toàn vẹn.
\end{itemize}

\subsection{Mức cài đặt}
Sinh ngẫu nhiên đúng cách, lưu IV an toàn, xác minh tag, xử lý lỗi fail closed, rủi ro lưu key trong \texttt{std::string} chưa xóa an toàn khỏi bộ nhớ.

\subsection{Cân nhắc đa nền tảng}
\begin{itemize}
  \item Nguồn RNG: Linux \texttt{getrandom}/\texttt{/dev/urandom}, Windows CNG \texttt{BCryptGenRandom}.
  \item Hành vi file system: ghi file, kết thúc dòng, đường dẫn.
  \item Nguyên nhân khác biệt hiệu năng.
\end{itemize}

\subsection{Hạn chế của cài đặt}
Đọc toàn bộ file vào RAM, nonce registry chỉ bắt trùng IV chính xác, JSON parser tối giản.
